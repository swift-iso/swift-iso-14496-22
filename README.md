# swift-iso-14496-22

Use this package when you need to read a TrueType or OpenType font: its metrics and character map, the outline of a glyph as curves, and the kerning between two glyphs. It also cuts a TrueType font down to the glyphs a document uses, for example to embed it in a PDF. Start from `ISO_14496_22.FontFile` to parse a font, `ISO_14496_22.FontFile.outline(for:)` and `ISO_14496_22.FontFile.kerning(left:right:)` to read from it, and `ISO_14496_22.FontSubsetter` to subset one. It reads what the font file says and stops there: no hinting, no variations, no shaping and no line layout.

## Laws

- A font must start with one of the sfnt versions 0x00010000, "OTTO", "true" or "typ1", and must have `head`, `hhea`, `maxp`, `hmtx`, `cmap`, `name` and `post` tables. `loca` and `glyf` are optional, so a CFF-based OpenType font parses but can't be subset. `CFF `, `kern` and `GPOS` are kept as bytes when present and read only when an outline or a kerning value is asked for, so damage in them never stops the font from parsing.
- Of the `cmap` subtables, one is used, chosen in this order: Windows full Unicode, Windows BMP, Unicode full, Unicode BMP, any other Unicode subtable. Only formats 4 and 12 are read. Any other format gives an empty mapping, not an error.
- A code point that maps to glyph 0 counts as unmapped, so `ISO_14496_22.CmapTable.glyphIndex(for:)` returns nil for it.
- Of the `name` records, only English ones (language 0x0409 or 0) are decoded, and the first for each name wins. Windows and Unicode records are read as UTF-16BE, Macintosh records as UTF-8.
- `ISO_14496_22.FontFile.postScriptName` falls back to the family name, then to `Unknown`.
- A glyph past the last full metric in `hmtx` takes the last advance width. `ISO_14496_22.FontFile.advanceWidth(for:)` with an unmapped code point gives the width of glyph 0.
- A subset always keeps glyph 0 as glyph 0, and every component a composite glyph refers to, however deeply nested. The kept glyphs are renumbered in ascending order of their old IDs, and composite references are rewritten to match.
- A subset holds only `head`, `hhea`, `maxp`, `hmtx`, `cmap`, `loca`, `glyf`, `post` and `name`. Every other table, including OS/2, kerning, layout and hinting tables, is dropped.
- A subset's `cmap` is one Windows BMP format 4 subtable for the requested characters. A character above U+FFFF keeps its glyph but loses its mapping.
- A subset's `name` table holds only the PostScript name, and its `post` table is version 3, without glyph names. The `head` checksum adjustment is written as 0.
- A subset uses the short `loca` format when its glyph data is at most 0x1FFFF bytes, and the long format otherwise.
- An outline is a `Geometry<Double, ISO_14496_22.Unit>.Path` in the font's design units, y up, with one closed subpath per contour, in the font's contour order and direction. Divide by `unitsPerEm` yourself. Hinting instructions are not run and variation data is not applied, so the outline is the unhinted default instance.
- TrueType curves stay quadratic, with three control points, and CFF curves stay cubic, with four. Nothing is raised, flattened or merged.
- A TrueType contour starts at its first on-curve point, or halfway between its last and first points when it has none. Two off-curve points in a row imply an on-curve point halfway between them. A closing line is added only when the contour does not already end where it started. A contour of one point, and a CFF move with nothing drawn after it, give no subpath.
- A TrueType outline is moved so that the glyph's left side bearing point is at x 0: every x changes by the `hmtx` left side bearing minus the glyph's own `xMin`. A composite uses its own bearing and `xMin`, or those of a component flagged USE_MY_METRICS. FreeType and HarfBuzz do the same. A CFF outline is as its charstring draws it.
- A composite's component is transformed first and offset second. With SCALED_COMPONENT_OFFSET alone, the offset is multiplied by the lengths of the matrix columns, as FreeType does. With UNSCALED_COMPONENT_OFFSET, both flags or neither, it is not. Point numbers place a component so that its point meets the point already in the composite. A composite that contains itself, or nests deeper than 64, fails with `ISO_14496_22.Outline.Error.nesting`.
- From `CFF ` the first font is read, CID-keyed or not, with Type 2 charstrings. The font matrix is not applied. The charstring's width is dropped, hints are counted and skipped, the stack holds 48 numbers and subroutines nest 10 deep. Drawing before the first move starts at the origin. A charstring that uses `random` or the deprecated four-argument `endchar`, and a `CFF2` table, fail with `ISO_14496_22.Outline.Error.unsupported(_:)`.
- Outline data that is cut off or contradicts itself fails with `ISO_14496_22.Outline.Error.malformed`, a glyph the font does not have with `glyph(_:)`, and a font with neither `glyf` nor `CFF ` with `absent`. Nothing traps.
- `ISO_14496_22.FontFile.kerning(left:right:)` gives the change to the advance between two glyphs, in design units. When `GPOS` has a `kern` feature it is the first glyph's advance adjustment from there, and the `kern` table is not consulted, also for a pair `GPOS` does not list. Otherwise it comes from `kern`, and it is 0 when the font has neither.
- `ISO_14496_22.GPOS.pair(first:second:feature:script:language:)` returns nil when the language system has no such feature, and both value records, zero when no lookup applies, when it has. The script is the one asked for, then `DFLT`, then `latn`. The language system is the one asked for when the script has it, the script's default otherwise.
- Pair adjustment reads lookups of type 2, also inside extension lookups of type 9, in both formats. A lookup stops at its first subtable that applies, and lookups add up in lookup list order. Device and variation offsets in a value record are skipped. Lookup flags are not consulted: the second glyph is the one you pass, so skipping marks is the caller's.
- `ISO_14496_22.Kern.adjustment(left:right:)` reads version 0 with subtable formats 0 and 2, and fails with `unsupportedFormat` for any other version. Only horizontal subtables that are not cross-stream count. Their values add up in table order, an override subtable replaces the sum, and a minimum subtable raises it to its value.
- An `ISO_14496_22.Tag` made from text is four bytes, padded with spaces.
